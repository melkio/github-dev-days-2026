## 2. Ownership dei file

- **Backend:** tutto `src/TaskFlow.Api/**` (incluse migrazioni), `README.md`, `docs/architecture.md`, `SPECIFICATIONS.md`. File toccati: `TaskItem.cs`, `TaskDtos.cs`, `TaskEndpoints.cs`, `TaskService.cs`, nuovo componente calendario, `AppDbContext.cs`, `Migrations/`, `DbSeeder.cs` (solo se necessario).
- **QA:** `tests/TaskFlow.IntegrationTests/**` (`TaskEndpointsTests.cs`, nuovi file per feature, `Infrastructure/*` incluso un clock modificabile).
- **Orchestratore:** integrazione, verifica finale, gate di approvazione.
- Conflitti: `TaskEndpoints.cs` e `TaskService.cs` hanno un solo owner (Backend), quindi T3, T4 e T5 sono sequenziali sullo stesso file o vanno su rami coordinati.

- T6 (QA) in parallelo a tutto il lavoro Backend, sui contratti di §4 del design; non tocca `src/`.
- T7 in parallelo a T6 dopo T4/T5.

## 4. Test e controlli richiesti

`WebApplicationFactory` con SQLite in-memory isolato e clock controllabile (la factory deve consentire di impostare l'ora).

- Assegnazione: creazione con/senza assegnatario e scadenza; assegnatario inattivo/inesistente → `400` e nessuna assegnazione; sostituzione e rimozione; assegnazione su task con scadenza passata consentita.
- Scadenza: oggi accettata; passata rifiutata (`POST` e `PATCH`); aggiunta, modifica e rimozione su scadenza oggi/futura; scadenza passata → `409` e valore invariato (anche valore identico); modifica di titolo/descrizione/stato con scadenza passata; completamento di task scaduto.
- Done: `PUT`, `PATCH status` (Done→Todo/InProgress/Done), `PATCH assignee`, `PATCH due-date`, `DELETE` → `409` e task invariato; vale per task seed già Done; nessun valore aggiungibile a Done senza assegnatario/scadenza; `404` su task inesistente.
- Elenchi: per utente (con Done) e con `status`; non assegnate; scadute (Done e senza scadenza esclusi, oggi/domani non scadute, ieri scaduta); scadute+utente e scadute+non assegnate; ordinamento scadute con parità; elenco vuoto; `assigneeId` inesistente → `200 []`; `assigneeId`+`unassigned` → `400`; booleano/GUID invalido → `400`.
- Tempo: scadenza 25 ottobre non scaduta per tutto il giorno italiano e scaduta dal 26; giorno UTC ≠ italiano (es. 23:30Z vs 00:30 locale); passaggi DST (ottobre e marzo).
- Migrazione: applicazione su DB con dati v1.0 (inclusi Done): colonne `NULL`, dati invariati.
- Regressione: test v1.0 esistenti aggiornati solo dove il comportamento Done cambia intenzionalmente (`UpdateStatus` e `DeleteTask` su seed Done); `Health` e `Users` invariati.
- Verifica che `Europe/Rome` sia disponibile nell'ambiente (test dedicato).
- Controlli finali (Orchestratore): `dotnet build`, `dotnet test` verdi dalla root.

- `dotnet build` e `dotnet test` verdi; nessun file modificato fuori dall'ownership prevista.
